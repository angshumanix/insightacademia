# InsightAcademia demonstration library

A static educational sample catalogue using HTML/CSS/JavaScript, generated by Python's standard library. The public site displays only demonstrations and sample PDFs. Full-pack availability, pricing and any purchase arrangements are discussed privately through https://t.me/InsightAcademiaPacks.

## Build and review

```
python scripts/build.py
python scripts/preview.py
python -m http.server 8765
```

The default build contains 18 noindex demonstration/information pages. `.preview/InsightAcademia_Design_Preview.html` is a self-contained offline review with navigation and desktop/768/390/320px controls. No command deploys. Serve only a reviewed static export publicly, never repository source or private records.

## Source and maintenance

- `data/demonstrations.json`: only public sample metadata, local preview and sample PDF paths, sample page count and individual approval flag. No prices or full-product records are accepted.
- `data/site.json`: seller identity and independent seller/policy/library/deployment approval gates.
- `templates/`: shared head/navigation/footer and demonstration detail layout.
- `scripts/build.py`: static generator and preserved internal pricing validation helpers. Public generation never reads `products.json`.
- `data/pricing-bands.json`: seven approved internal bands. `data/products.json` preserves artificial Phase 2 model examples only; it is not real stock. This repository is public: confidential full-product metadata must be kept elsewhere, as must paid files and all customer records.
- `assets/`: intentionally public SVG branding, educational previews and two-page sample PDFs.
- `scripts/build_samples.py`: optional sample authoring, requires ReportLab. PDFs are committed; rendering or regeneration is not required to build the site.
- `docs/`: branding, pricing, private-record procedure and review notes.

Edit source then regenerate. `.generated-pages.json` tracks managed pages and removes withdrawn generated pages. The legacy services.html route remains a noindex bridge; how-to-order.html retains its old URL but is labelled How it works. Existing Git history is retained.

## Tests

```
python -m pip install pypdf
python -m unittest discover -s tests -p 'test_*.py'
node --check js/main.js
node tests/interactions.cjs
```

Real browser QA is `node tests/browser.cjs`, with Playwright installed in the QA environment only. `CHROMIUM_PATH` can select a system executable; otherwise Playwright uses its bundled Chromium. The GitHub Actions QA workflow uses a standard free public-repository Ubuntu runner, read-only access and no deployment, artifact upload, cache, secrets or paid runner. See docs/REVIEW.md for observed results.

## Release gate

`python scripts/build.py --release --out .preview/release` generates indexable demonstration output only; it never deploys. It requires nonblank seller identity, `sellerDetailsApproved`, `policiesApproved`, `demonstrationsApproved` and `deploymentApproved`, plus `approved: true` on every demonstration. Full commercial inventory is neither required nor permitted as public input. Approving a flag does not rewrite policy drafts; finalize the prose and obtain owner/legal/hosting approval first.

Keep main, Pages settings and DNS unchanged until explicit launch approval. Catalogue-only positioning does not itself resolve GitHub Pages' commercial-use restrictions.
